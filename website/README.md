# RecordPlus Website

Static marketing site for RecordPlus — HTML + Tailwind CSS.

## Prerequisites

- [Node.js](https://nodejs.org/) (v18+ recommended)

## Setup

```bash
cd website
npm install
```

## Development

Watch and rebuild CSS on file changes:

```bash
npm run dev
```

Open the site locally (from the `website/` folder):

```bash
npx serve .
```

Then visit `http://localhost:3000` (or the port shown).

## Production build

Generate minified CSS before deploy:

```bash
npm run build
```

Deploy the `website/` folder to any static host (Cloudflare Pages, Netlify, GitHub Pages). Exclude `node_modules/` from upload.

## Pages

| File | Purpose |
|------|---------|
| `index.html` | Landing page |
| `privacy.html` | Privacy Policy |
| `data-policy.html` | Data Policy |
| `contact.html` | Contact form (emails `support@recordplus.app`) |

## Contact form

Same pattern as a secured PHP contact flow:

- **`contact-token.php`** — issues CSRF token + form timestamp (JSON)
- **`contact.php`** — validates, rate-limits, sends to **support@recordplus.app** via PHP `mail()`
- **`contact.html`** + **`js/main.js`** — loads token, submits via AJAX

### Deploy requirements

- Host must support **PHP** with sessions (cPanel recommended).
- Upload `contact.html`, `contact.php`, `contact-token.php`, and `js/main.js`.
- Not supported on static-only hosts (GitHub Pages without PHP).

### Local testing

```bash
cd website
php -S localhost:8080
```

Open `http://localhost:8080/contact.html`. `mail()` may fail on Windows locally; test on **live cPanel** for real delivery.

### Troubleshooting

- **“Security validation failed”** — refresh the page (CSRF token expired).
- **No email received** — check spam; confirm `support@recordplus.app` exists; test on production server (not localhost).
- First activation not required (unlike FormSubmit).

## Replacing placeholders

### App store links

In `index.html`, update the `#download` section links:

```html
<a href="YOUR_APP_STORE_URL">App Store</a>
<a href="YOUR_PLAY_STORE_URL">Google Play</a>
```

### Images

See **[MEDIA_PROMPTS.md](MEDIA_PROMPTS.md)** for app functionality and feature context to use when creating media assets.

Replace SVG placeholders in `assets/images/` with real screenshots or export previews:

- `hero-app-placeholder.svg` — app home/record screen
- `document_register_image.png` — Document Register PDF preview
- `financial_statement_image.png` — Financial Statement PDF preview
- `og-image.svg` — social sharing image (1200×630 recommended)

Update `src` attributes in `index.html` if you change filenames or use `.png`/`.webp`.
